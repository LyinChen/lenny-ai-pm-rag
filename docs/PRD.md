# Lenny AI-PM 知识库问答 PRD

## 1. 背景与问题
入门 PM 做 AI 产品时缺少一线经验参考，行业访谈内容多且是英文，难以检索。

## 2. 目标用户
0-2 年经验、正在做或将要做 AI 功能的产品经理。

## 3. 核心场景
- 场景A：写 AI 功能需求时，查"别人怎么做"
- 场景B：为 AI 产品定义成功指标
- 场景C：遇到具体困境（如用户不信任 AI 输出），找案例和建议

## 4. 产品定位与功能范围（MVP）
- 定位：由 Agent 判断是否需要查资料的 AI 助手，检索是 Agent 的工具之一
- 做：中文提问 → 检索英文资料 → 中文回答 → 显示引用来源
- 不做：用户登录、全量付费数据、多轮复杂推理

## 5. 数据范围
- 来源：Lenny's Newsletter & Podcast 公开数据集
- 规模：60 篇（50 播客 + 10 newsletter），约 86.6 万词、115 万 token
- 结论：超过 1M 上下文，无法整库放入单次提问，需要检索
- 版权：不公开转存原数据，README 指向原仓库

## 6. 成功指标
| 类型 | 指标 | 目标 |
|---|---|---|
| 检索 | Hit Rate@5 | ≥ 80% |
| 生成 | Faithfulness | ≥ 0.8 |
| 行为 | 库外问题正确拒答 | 100% |
| 引用 | 每条回答都带来源（标题+嘉宾+日期） | 100% |
| 引用 | 有链接的来源，链接可点击 | 100% |
| 工程 | 响应时间 | < 10 秒 |

## 7. 边界规则
- 库内问题：基于检索结果回答并附引用
- 库外问题：明确告知"知识库中未找到"，不凭模型自身知识作答
- 闲聊：直接回应，不触发检索

## 8. 引用规则
- 有 youtube_url 用它，否则有 post_url 用它，否则无链接
- 链接不全时，最低保证展示：标题 + 嘉宾 + 日期 + 时间戳
- 不自行拼接链接；无链接的来源标注"暂无原文链接"
- 数据现状：无链接 14 篇（均为播客，占播客 28%）

## 9. 风险
- 跨语言检索不准（中文问、英文答）
- 模型编造（幻觉）
- 数据版权
- 部分播客无原文链接，引用体验不一致

## 技术路线与依据
- 数据：4.7MB 纯文本。token 早期按"词数÷0.75"估为 115-123 万；Day 4 按 bge-m3 用量反推
  实际约 1.57 token/词，清洗后约 128 万（校准后以此为准；两种口径都超过 1M 上下文）
- 选择 RAG 而非整库长上下文，依据：
  1. 每问输入量约为整库方案的 1/380（未计缓存），20 道验收题的成本差约两个数量级
  2. 可用对话模型的上下文长度（原列为待核实项；实际每问只送前 5 个块，约 1,500 词，
     远低于任何现代对话模型的上限，此项已不构成约束）
  3. 引用的嘉宾、时间戳、链接由块的元数据直接带出，不依赖模型回忆
- Agent 层范围：判断是否检索、无命中拒答、复杂问题多次检索；其余不做

## 评测口径（修订）
- 原口径：块级（单块能否直接回答），Hit@5 目标 ≥ 80%，实测 60%，目标不改
- 新口径：回答级（行为通过率 = 符合期望的题数 ÷ 30，分 A/B/C/D 档，附差异清单）
- 原因：访谈稿的建议分散在多个块里，最终回答由多块综合，单块标准对检索不公平

## 检索与拒答
- 检索：中文原问题 → 向量检索 → 重排序；暂不使用改写和混合检索
  （B 版同时改了三件事，无法归因；两个探针中，改写在 Q19 更差，在 Q02 持平，样本仅 2 题）
- 拒答第一道：向量最近距离 > 0.47（临时值，仅 28 个数据点；半相关题与库内题距离重叠）
- 拒答第二道：回答提示词要求依据不足时明说，此判断只作标记
- 人工审核：所有系统拒答 + 期望拒答题全审，A/B 类抽 1/3

## 回答风格
- 先给一句结论，最多 3 个要点，每点附来源；追问时再展开
