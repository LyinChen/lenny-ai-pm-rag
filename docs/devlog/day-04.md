# Day 4｜向量索引与检索诊断

## 一句话
把 2,806 个文本块变成"数字坐标"存进数据库，验证中文提问能搜到英文资料，并发现"搜不准"的主要原因是提问用词和资料用词不一致。

## 今天做了什么
1. 冒烟测试：先用 3 句话确认接口、维度、跨语言可行
2. 建库：用 bge-m3 把 2,806 个块向量化，存入 Chroma
3. 验收：检查数量、元数据、距离含义，并试搜
4. 诊断：查"搜不准"是资料少还是用词不对
5. 写题单：30 道评测题，每题标注类型和期望行为

## 学到的概念（大白话）
| 词 | 含义 |
|---|---|
| 向量化 | 把一段文字变成一串数字，相当于它的"坐标" |
| 余弦距离 | 两个坐标有多远，越小越像（相似度 = 1 − 距离） |
| 向量数据库 | 存这些坐标，并能按"意思相近"快速找回 |
| 冒烟测试 | 正式开工前，用最小成本先确认这条路能走 |
| 断点续跑 | 中途失败后重跑，只补没做完的部分 |

## 选择依据
- 选 bge-m3：官方文档写明它的单次输入上限是 8192 token，其他 bge/bce 模型只有 512；我们的块最大约 530 token，超过 512
- 距离含义：用库里存的向量手算 1−余弦 = 0.427，与数据库报告的距离完全一致，确认是余弦距离

## 发现
1. **用词不一致是"搜不准"的主要原因**：资料里 "success metric" 出现 0 次，而 "evals" 出现在 53 个块、11 篇文档里（按 `\bevals\b` 只算复数；若连单数 `eval` 一起算，是 59 个块、12 篇）
2. **换成资料的说法，结果明显更对题**：问 "how to write evals" 距离降到 0.256-0.328，前 5 名全是 Beyond vibe checks 的正文；之前问"怎么定义成功指标"是 0.38-0.41
3. **距离接近 ≠ 能回答问题**：前 5 名距离只差约 0.02，但我逐条读原文后初判只有 1 条能直接回答（Claude 初判，仅 1 题，待本人复核）
4. **库外问题会命中"诱饵"**：例如题单里问国内合规，命中的是"中国监控""印度和中国移民"，不能拼成答案
5. "成功指标"有两种意思（业务指标 / 质量指标），资料用不同词表达（north star、KPI / evals）

## 踩坑与解决
| 问题 | 原因 | 解决 |
|---|---|---|
| 所有块的文档名都变成 `None` | 我取的字段名 `doc_id` 与框架的保留字段同名，被覆盖 | 改名为 `source_doc`，删库重建，并在 `check_index.py` 里加"元数据完整性"检查 |
| 数量对得上，内容却是错的 | 只看了"入库 2806"，没有回读具体内容 | 以后写入第三方系统后，要回读核对内容 |
| 我设的"文档重合数"指标不合理 | 两种问法不必搜出同一批文档，只要各自相关 | 改成人工判断相关性 |
| token 估算偏低 | 按词数÷0.75 估算，实际约 1.57 token/词（按账单反推，假设两次建库是全部用量） | 费用和用量以账单为准 |
| 我之前夸大了一条结果 | 只看了片段前 70 个字符就说"找到了相关段落" | 读完整原文后更正 |
| 提交身份是自动生成的假邮箱 | 没设置 git 身份 | 设为 GitHub 隐私邮箱，之后的提交生效 |

## 题单设计（30 道）
| 类型 | 数量 | 期望行为 |
|---|---|---|
| 库内 | 20 | 基于资料回答并附来源 |
| 库外·半相关 | 5 | 不编造，明说"知识库中未找到" |
| 库外·无关 | 3 | 说明超出范围，不检索 |
| 闲聊 | 2 | 直接回应，不检索 |

关键词粗筛：库内题每题至少 10 块、6 篇文档命中，没有发现标错类型；半相关题仅有零星命中，且是"诱饵"（Q25 跨境电商：`cross-border` 严格匹配 0 块，但 Shopify 命中 13 块、e-commerce 命中 7 块——主题是美国电商，不是跨境电商，看得见但答不了）。

## 反思
- 评价检索质量要靠人读结果，分数只是辅助
- 先诊断再动手：同样是"搜不准"，可能是用词、内容缺失或切块问题，药不同
- 数据库是可再生数据，脚本重建比手工修补更稳
- 题单必须有"期望行为"，否则 Day 11 无法打分
