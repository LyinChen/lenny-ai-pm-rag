# Day 5｜检索改进与评测

## 今天做了什么
- 实现提问改写、BM25 关键词检索、向量检索，并用 RRF 合并
- 用大模型评审 20 道库内题，对比改进前后；写探针脚本检查"已知好内容"的排名
- 修订评测口径和验收方案（细节见 docs/day5-summary.md）

## 学到的概念
- 提问改写：让大模型把用户的话翻成资料里可能用的说法
- BM25：按词对不对找，像 Ctrl+F，抓专有名词强，不懂同义词
- 混合检索 + RRF：两种搜法各出一份名单，名次都靠前的得分高
- LLM 评审：让大模型当评审员，必须人工抽检校准
- Hit@5 / P@5 / MRR：衡量前几名里有没有、有多少、排多前

## 数据（口径见总结文档，两轮不可直接比较）

## 踩坑与反思
1. 一个例子不能当证据。Day 4 凭一道题就说"改写有效"，20 题没有复现。
2. 同时改了三件事，没法知道哪件出了问题。以后一次只改一个变量。
3. 评审标准一改，数字就不可比。每份结果文件必须写明口径。
4. 改写步骤每次结果不同（同一道题两轮改写不一样），不可复现的步骤无法作为验收对象。
5. 我先后两次在没有证据时下判断：一是"Q19 的好块在前 5 名却被判无关"（实际排第 6），
   二是"估算用量偏高近 8 倍"（实际整轮偏高约 1.5 倍）。看数据再下结论。
6. 探针命令里多一个空格，排名就从 6 变成 5；小的输入差异会改变结果。
